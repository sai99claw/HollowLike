# v0.20 玩家體驗修正

## 死亡選擇

鍵盤 `_input`、手把 `_unhandled_input` 與觸控 `_set_action` 統一進入相同的死亡選單導航分支，允許攻擊／互動鍵確認與方向鍵選擇。確認後立刻切換為靈魂返程；原有重傷、死亡擊飛及靈魂飛行仍拒絕戰鬥輸入。鍵盤重複事件不能誤觸死亡確認。

驗證走實際受傷死亡、落地、開啟選單、X 確認、回到最近整備點，另測有符文的選擇與手把 X；沒有直接呼叫選擇函式代替按鍵測試。

## 攻擊與能量回饋

左上狀態新增常駐的攻擊準備列：可出擊／前搖／攻擊中／後搖、當前階段剩餘秒數、階段進度。後搖附目前綁定的衝刺取消鍵。修正先把狀態翻成中文字再傳給僅識別英文狀態的 HUD 問題。

大刀原先約 2.036 秒的第一段週期保留；其中 1.876 秒後搖會明確顯示倒數。忙碌時再按攻擊顯示「尚未就緒」，受傷硬直與未裝備副武器有各自提示。衝刺取消或攻擊結束會清掉過期的忙碌提示。

副武器能量不足時，能量數字與格子短暫閃橘色，提示每次消耗一格、可近戰命中回能。提示短暫限頻，使用既有控制項，不配置連續粒子；能量警示約 0.8 秒後還原。成功出招立即清掉失敗提示。所有被拒絕的出招點擊仍直接丟棄，不排隊、不補發、不額外消耗能量。

## 地形決定通路

原先所有戰鬥房都用左右兩排每 96px 一層的單向平台，加上整排頂部走道，造成地形中央雖然變化，主要路線仍重複。

新增 `maze_routes_v20.gd`，在當前 Prim／廣場／環路地形的可通行格子中，依房間種子、岩塊與門位置計算一組共用連接路線。天然岩頂成本較低，外側固定邊帶成本較高，同成本路徑由種子打破平手。只對必要路線的懸空部分建立單向平台，相鄰水平段合併為橋；不對岩頂重複加碰撞面。每一層仍為 96px，使用原有跳躍能力即可通行。

門寬仍為三格，功能房與 Boss 場保留原內裝通路。修正底門附近的必要單向橋被舊版支撐面重建步驟移除的問題；橋可下穿，不會封住底門。已生成房間不遷移，新冒險／練習套用新生成。

10 個固定種子、169 個戰鬥房：必要導航平台共 1,479 個，舊雙梯方式為 3,228 個；每房導航平台占比的中位數為 42.1%，先前相同抽樣約 60.9%。另外比較平台總長度，避免只靠合併物件降低數量。`test_routes_v20.gd` 使用實際身體碰撞與跳躍／下落控制建立可達圖，檢查每個出口可抵達且可返回中心，沒有用格子連通取代物理檢查。

## 驗證與限制

33 組原始碼測試完成驗證（含修正後的 v17 通道寬度契約），17 組匯出資源包測試全數通過。新增輸入／回饋回歸測試與跨種子雙向物理可達測試，加入 Web 資源包驗證。中文字型重新收集新增提示字元。瀏覽器 GPU 畫面、音效與 FPS 仍需支援 WebGL 2 的環境實測；無畫面的控制器測試不能代替視覺手感驗收。
