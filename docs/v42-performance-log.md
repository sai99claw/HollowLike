# v0.42 效能錄製與回報

## 玩家操作

1. 重新整理載入 v0.42，進入有低 FPS 的空房。
2. 點右下角「效能紀錄」→「開始錄製」。遊戲會繼續，不需要開開發者工具。
3. 原地停約 10 秒，再走動、換房或攻擊，總共錄 30～60 秒。感覺卡頓時點「標記卡頓」。
4. 點「停止並顯示報告」→「複製整份報告」，將含 PIGEON_PERF 開頭及 END 結尾的文字貼回聊天；也可下載 TXT。
5. 開啟報告後遊戲會暫停，按「關閉」繼續。最長 120 秒自動停止。完成的最後一份報告保存在同一瀏覽器，重新整理後可再次開啟取回；新錄製完成才覆蓋它。

剪貼簿權限不足時，自動選取文字並提示 Ctrl+C／⌘C。離開／重新整理前請先停止；尚未完成的錄製不會逐幀寫入硬碟。

## 報告內容

- ENV：遊戲及 Godot 版本、release/debug、平台、FPS 上限、VSync、瀏覽器 UA、硬體執行緒數、DPR、視窗／CSS／Canvas／WebGL buffer 尺寸、可取得的 GPU vendor/renderer，以及軟體繪圖提示；保留最多 16 次分頁隱藏／回到前景的事件，避免切分頁造成的停頓被誤認為遊戲 GPU 問題。
- SUMMARY：單調時鐘量到的實際 process 回呼間隔，平均／p50／p95／p99／最大幀時間、超過 33.333ms 的比例及錄製長度。這與遊戲提供的 delta 不混為一談。
- CPU_SPANS：process、physics、主場景繪圖、背景／地形／前中景／屍體等保留畫布重建、敵人畫布重建、主角／敵人／彈體／陷阱／掉落／場景物件／攻擊／被動／夢境更新、HUD、景深層更新；提供每次呼叫平均／最慢及按實際 render frame 換算的平均。物理常以 60Hz 執行，因此低 FPS 時可能每個 render frame 包含多次 physics 呼叫。
- SECONDS_JSONL：每秒與換房的場景快照，包含模式／房型／房間／關卡、暫停或命中停頓、精簡特效與鏡頭倍率、怪物總數及畫面內數量、彈體／陷阱／掉落／特效數、可見啟用的粒子發射器與設定數量預算、引擎 draw calls／primitives／CPU monitor／記憶體及渲染尺寸。粒子預算是發射器 amount 的合計，不是假稱已實測存活粒子數。
- MARKS、WORST_FRAMES：手動標記／換房事件與最慢十幀。最慢幀場景標籤以最近快照為準，換房附近不聲稱是精確 GPU attribution。

## 解讀限制

CPU 區段是包含式計時，父層與子層不可相加。腳本 `_draw` 測量繪圖指令建立時間，不是 GPU 執行時間。實際幀間隔還包含引擎、驅動、GPU、瀏覽器 compositor、VSync、分頁節流及未計時工作，不能直接用「幀時間減 CPU」當作 GPU 毫秒。GPU 時間明確標為未量測；部分平台回傳零的 VRAM monitor 也可能代表不支援。

紀錄預設關閉；關閉時不讀時鐘、不累積資料。開啟後每秒取一次完整快照，不逐幀列印、不逐幀寫檔；記憶體上限為 8192 個幀間隔樣本、180 個快照、32 個標記及十個最慢幀。超過幀樣本上限時百分位採最近 8192 幀，整段平均／最大值仍涵蓋完整錄製。報告單獨計時 `recorder.snapshot` 以顯示取樣成本，但計時器本身仍有少量開銷。

## 資料與測試

只在玩家選擇複製／下載後分享；程式沒有自動上傳路徑，不讀帳號、存檔或網址參數。瀏覽器僅使用獨立的 `pigeon-perf-last` 本機儲存鍵。原生測試可把完成報告寫至 `user://pigeon-perf-last.txt`，不寫入遊戲存檔。

`tests/test_performance_log_v42.gd` 覆蓋停用、20 FPS 回呼間隔／單位、零幀停止、重啟、容量上限、120 秒自動停止、實際 process／physics／draw 計時、快照、標記與安全暫停。`tests/test_performance_browser_v42.mjs` 覆蓋開始／標記／停止／複製／TXT 下載、解析度／WebGL 資訊、剪貼簿失敗備援與不支援 WebGL／本機儲存的處理。發布流程另驗證實際 PCK 及 JS 檔案進入完整主機輸出。
